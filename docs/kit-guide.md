# 교안 갤러리 공통 규칙 (kit-guide, 계약 v2)

모든 교안 갤러리(UI, 셰이더, 디자인 패턴, C# 문법 …)가 같이 지키는 규칙이다. 갤러리의 `docs/specimen-guide.md` 는 도메인 규칙만 쓰고 공통 부분은 이 문서의 절을 링크한다. 타입은 [`src/contract.ts`](../src/contract.ts), 설계 근거는 [design.md](design.md).

## 1. 표본

표본 하나는 교안 한 장이다. 네 가지로 이루어진다.

1. **무대에서 움직이는 실례.** 무대는 갤러리가 종류별로 하나 이상 제공하고, 표본은 무대를 꾸미지 않는다.
2. **원본 코드.** 수강생이 Unity 에 그대로 넣는 코드다. 웹 미리보기와 갈리지 않게, 웹은 원본을 직접 실행하거나, 원본을 실제로 실행한 기록을 재생하거나, 같은 시나리오를 양쪽에서 돌려 결과를 기계로 대조한다.
3. **글 (meta.ts).** 목표, 단계, 흔한 실수, 넣는 순서, 프롬프트 재료.
4. **실측 결과.** Unity 컴파일·촬영, dotnet 실행 기록, 웹 무대 촬영 등 도구가 만든 것.

- `id` 는 **영구 불변** kebab-case 영어다. 폴더 이름과 `meta.id` 가 같아야 한다. 바꿔야 하면 갤러리 설정 `aliases` 에 옛 id 를 남긴다.
- 표본 작업은 자기 폴더만 고친다. 셸(`@koohoo/gallery-kit`), 갤러리 공통 코드, 다른 표본은 고치지 않는다. 공통 기능이 필요하면 작업 결과에 **무엇이 왜 필요한지** 요청으로 적는다.

## 2. meta.ts 글쓰기

글은 수업에서 그대로 읽을 수 있게 한국어로 짧게 쓴다. `**굵게**`, `` `코드` ``, `[링크](https://...)`, `[다른 표본](#/s/<id>?preset=...)` 를 쓸 수 있다.

| 필드 | 규칙 |
|---|---|
| `title` `titleEn` | 표본 이름. 게임명 금지 |
| `group` `order` | 갤러리 설정 `groups` 의 키와 그룹 안 순서 |
| `oneLiner` | 한 문장. 무엇을 하는 표본인지 |
| `goals` | 3~4개. "~할 수 있다" |
| `tags` | 기법·주제 2~5개. 검색과 필터에 쓴다 |
| `difficulty` | 1~3 (선정 문서의 별 수) |
| `params` | 모든 값이 화면에 **눈에 띄는** 차이를 만들어야 한다. `key` 는 **원본 코드의 이름**(셰이더 속성, `[SerializeField]` 필드, 시나리오 입력 변수). `hint` 로 무엇이 바뀌는지 적는다. 다른 select 값에 따라 쓰이지 않는 값은 `showWhen` 으로 숨긴다 |
| `presets` | 2~5개. 쓰임새 이름(게임명 금지). `values` 에는 기본값과 다른 것만 |
| `events` | 9개 이하 (단축키 1~9). `tracks` 는 range 값만 움직이고, 트랙 값은 절대값이라 프리셋·슬라이더가 바꾸는 값을 움직이면 시작과 끝에서 튄다. 이벤트는 0 에서 올라갔다 0 으로 돌아오는 더하기용 전용 값을 움직인다 |
| `demo` | 사람이 없어도 핵심 상황이 돌게 |
| `steps` | 2~5개, `n` 은 1부터 차례로. 무엇을 보고 무엇을 이해해야 하는지. 앱이 최종 화면을 따로 보여 주므로 마지막 단계가 최종과 같으면 넣지 않는다 |
| `offNote` | 효과 끄기 화면이 보여 주는 **흔한 실수**. 그냥 안 보이는 것은 안 된다 |
| `mistakes` | 3~5개. 수강생이 겪을 **증상**을 제목으로, 원인과 해결을 본문으로. '문제 해결' 프롬프트에 그대로 들어간다 |
| `unity.setup` | 넣는 순서 2~7단계. 메뉴 이름을 정확히 (Unity 6.3 기준) |
| `unity.verify` | 잘 되었는지 확인하는 한 문장 |
| `unity.pitfalls` | 2~6개. 설정, 플랫폼, 버전 제약 |
| `prompt.goal` | 프롬프트 첫 문장 |
| `prompt.adaptIdeas` | 2~6개. 수강생이 실제로 원할 변형. 첫 번째가 예시 칸에 들어간다 |
| `captures` | 기본값 외에 찍을 상태 3개 이하 (용량) |
| `inspiredBy` | 확인된 대표작만. `원제 (연도)`, 빌린 축 최대 2개. 근거가 없으면 빈 배열 |
| `original` | 무엇을 새로 만들었는지 |
| `references` | 1~6개. 원리의 출처 |
| `related` | 같은 갤러리는 `{ id, why }`, 다른 갤러리는 `{ url, title, why }` |
| `flashes` | 넓은 면이 번쩍이면 `true`. 이벤트가 제한기를 거친다 |

프롬프트, Skill, 코드 탭은 이 데이터와 원본 코드에서 자동으로 만들어진다. 표본에서 프롬프트 문장을 직접 쓰지 않는다. `gallery check` 가 개수, 범위, 형식을 검사한다 ([src/lint.ts](../src/lint.ts)).

## 3. 콘텐츠 정책

- 원작 에셋, 스크린샷, 로고, 캐릭터, 전용 폰트, 고유 문구는 **0** 이다. 원작에서 빌리는 축은 **최대 2개**이고 나머지는 새로 만든다.
- 게임명은 `inspiredBy` 에만 쓴다. ID, 제목, 프리셋, 변수 이름, 화면 문구에는 쓰지 않는다.
- 튜토리얼, 블로그, 책, 오픈소스 코드도 복사하지 않고 원리만 참고해 출처를 링크한다. 코드와 글은 새로 쓴다.
- 비트맵이 필요하면 코드로 만들거나 도구가 찍은 것만 쓴다.

### 공통 세계관

표본마다 따로 노는 설정 대신 하나의 가상 세계를 쓴다 (UI 갤러리에서 시작, 원작과 무관한 고유 설정).

- **외곽 탐사대**: 변방 행성의 궤도 정비 기지와 지표 탐사 구역
- 인물: **하린**(탐사대장), **도윤**(정비사), **세라**(통신 담당). 모두 아군
- 적: **잔해 드론**
- 아이템·자원: 수리 키트, 냉각 셀, 회로 조각, 산소 캔, 크레딧
- 화면 속 문구는 짧고 구체적으로: "냉각 셀 3개 회수", "북쪽 통신탑 복구"

## 4. 연구 규칙 (선정 문서를 쓸 때)

- 출처 우선순위: T1 개발자 강연(GDC, CEDEC, NDC)·인터뷰·공식 문서, T2 주요 매체 기사, T3 커뮤니티 글.
- 모든 주장에 출처 URL 을 붙인다. 인용은 15단어 이하로 하고 나머지는 자기 말로 요약한다.
- 직접 확인하지 못한 화면 묘사는 "미확인" 으로 밝힌다. 기억으로 연도와 제작사를 채우지 않는다.
- AI 접근이나 스크래핑을 금지한 사이트(gameuidatabase.com, interfaceingame.com 등)에는 접근하지 않는다. 403 이나 차단 응답을 받은 도메인은 다시 시도하지 않고 우회하지 않는다.

## 5. 안전 규칙

- 화면의 넓은 영역이 번쩍이는 효과는 초당 3회 이하다. 웹은 kit 의 `requestFlash()` 를 거치고(`meta.flashes = true`), Unity C# 도 같은 제한을 둔다: 실제 시간(`Time.unscaledTime`)으로 세고, 하한을 코드에 고정하고(`Mathf.Max(minInterval, 0.34f)`), `OnDisable` 에서 마지막 시각을 지우지 않는다.
- 반복 맥동은 2Hz 이하. 상대 밝기 10% 미만의 1Hz 이하 느린 맥동은 번쩍임으로 세지 않는다.
- 포화된 빨강(선형 RGB 에서 R/(R+G+B) ≥ 0.8 이고 (R−G−B)×320 > 20)을 넓게 깜빡이지 않는다. 화면 가장자리 띠에 머물게 하거나 어둡고 채도 낮은 색으로 바꾼다.
- 색만으로 상태를 전하지 않는다 (모양, 위치, 글자와 함께).
- 모션 줄이기 설정이 켜져 있으면 자동 데모로 시작하지 않는다 (셸이 처리).

## 6. 무대 계약

무대는 갤러리가 만드는 React 컴포넌트다 (`StageProps` → `StageHandle`).

- `values`, `step`(0 = 최종), `off`, `playing`, `speed`, `auto`, `startTime`(링크 `t=`)을 따른다. 멈춘 상태에서도 **한 번은 그린다**.
- `StageHandle`: `fire(id)` 이벤트, `capture()` 화면 PNG, `seek(t)` 검사용 시간 고정(null 이면 놓기), `status()` 그린 프레임 수·무대 시간·오류.
- 트랙을 쓰는 무대는 kit 의 `TrackPlayer` 로 이벤트·자동 데모를 돌린다.
- 무대가 키보드를 쓰면 `stageKeyDown` 또는 `useStageKeys` 로 갤러리 단축키(Space, 1~9, J, S, A, ←/→, P, Esc)와 부딪치지 않게 한다. 키를 먹는 것은 **무대에 포커스가 있고 그 키가 지금 상태의 조작 키일 때**뿐이다. 조합키와 입력 칸의 키는 가드가 거른다. 숫자 1~9 는 갤러리 이벤트라 표본 메뉴 단축키로 쓰지 않는다.
- 썸네일(`thumbnail`)일 때는 가볍게 그린다.

## 7. 검사와 완료

```bash
node tools/gallery.mjs check <id>          # 표본만 넣은 빌드: meta 규칙, 무대 동작(최종, 효과 끄기, 단계, 이벤트, 자동 데모), 도메인 검사
node tools/gallery.mjs live <id> --query="auto=0&t=1&step=2" wait:800 stage:step2
node tools/gallery.mjs live <id> --query="auto=0&t=1" wait:800 click:<이벤트> burst:event,6,100
node tools/gallery.mjs thumbs <id>         # 웹 무대 썸네일 (Unity 촬영이 없는 갤러리)
node tools/gallery.mjs unity-compile <id>  # Unity 내장 Roslyn 컴파일 (C# 9)
```

`live` 는 한 번에 `--query` 하나만 받는다. `burst` 는 무대 시간을 직접 옮겨 매번 같은 순간을 찍고, 시트 한 장과 이웃한 장의 변화량을 남긴다. 움직임을 말하는 글("흐른다", "튄다")은 정지 화면으로 확인되지 않으므로 이 시트로 확인한다. 만든 PNG 는 Read 로 열어 눈으로 본다.

합친 뒤의 전체 검사는 `npm run build`, `node tools/gallery.mjs skill`, `node tools/gallery.mjs check` 순서다. 전체 검사는 타입 검사, 용량 예산(원본 5MB, gzip 1.5MB, 90% 경고), 외부 참조, 네트워크를 막은 `file://` 실행, Skill 최신 여부까지 본다.

### 완료 체크리스트 (공통)

- [ ] `check <id>` 가 오류 없이 통과하고 경고도 원인을 확인했다
- [ ] 기본 화면이 의미 있게 보인다 (썸네일이 된다)
- [ ] 단계마다 화면이 달라지고 `body` 설명과 맞다
- [ ] 효과 끄기가 설득력 있는 나쁜 예다
- [ ] 모든 조절 값과 프리셋이 눈에 띄는 차이를 만든다
- [ ] 이벤트 버튼과 자동 데모가 동작한다
- [ ] 프롬프트 탭의 글을 처음부터 끝까지 읽어 빈칸이나 어색한 문장이 없다
- [ ] 게임명이 ID, 제목, 코드에 없다
- [ ] 맡은 폴더 밖을 고치지 않았다

## 8. 환경 함정

- PowerShell 5.1 의 `Get-Content`, `Set-Content` 는 UTF-8 한글을 깨뜨린다. 파일 편집은 전용 도구로, 커밋 메시지는 파일로 만들어 `git commit -F`. 제목 다음에 빈 줄.
- Python `Path.write_text` 는 Windows 에서 CRLF 로 쓴다. 셸 스크립트는 LF 로 체크아웃한다 (`.gitattributes`).
- 헤드리스 Chrome 스크린샷은 같은 경로를 다시 읽으면 이전 이미지가 보일 수 있다. 도구는 시각이 붙은 새 파일을 만든다.
- 브라우저 패널이 화면에 안 보이면 rAF 가 0 이다. 애니메이션 확인은 `live` 로 한다.
- Node 는 node_modules 안의 TS 를 읽지 못한다. 그래서 kit 의 TS 로직(meta 규칙, Skill 생성)은 빌드된 페이지의 `window.__gallery` 창구를 거쳐 헤드리스 Chrome 에서 돈다. 갤러리 도구가 kit 의 TS 를 직접 import 하지 않는다.
- 여러 파일을 스크립트 하나로 고친 뒤에는 grep 으로 결과를 확인한다. 정규식이나 Windows 경로가 든 수정은 Edit 도구로 한다.
